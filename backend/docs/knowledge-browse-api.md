# 知识目录与搜索（Issue #76）

本批是资料浏览搜索，不调用聊天模型、向量模型或搜索引擎，不改变已有 AI 检索/证据复核接口。

## 指南

沿用 `GET /api/v1/public/knowledge/guides`，不要求登录，一次返回完整公开文档快照目录（`id/title/revision`）；详情用 `?id=...`。

App 按标题包含关系搜索、忽略英文大小写。分类沿用 `GuideCategory.ts` 的标题规则，属于浏览粗分类，不是后端专业分类或故障诊断。正文摘要不在目录契约内，不补造；详情继续打开真实章节。

## 案例

新增 `GET /api/v1/knowledge/cases/search?q=线缆&page=1&pageSize=20`。

- 必须登录；原生请求使用 `X-Client-Type: native` 和 Bearer，兼容既有 Web 会话读取规则。
- 客户只搜索有效 PUBLIC 案例。有 `repair:read` 的工作人员/管理员可搜索 PUBLIC 与 STAFF；工作人员没有该权限时不通过客户接口绕过。
- 只返回 PUBLISHED，且至少有一条有效来源。每条已发布来源仍需备案 APPROVED、典型标记未取消、未删除、材料哈希一致；复用公开案例详情的有效性检查。
- `q` 去首尾空白后为 1–100 字符，匹配完整可见集合的案例标题或 `displayText`，忽略英文大小写；按更新时间及 ID 倒序。不是语义召回或相关度排名。
- `page` 从 1 开始，`pageSize` 默认 20，范围 1–100。**有效性过滤后再分页**；不限制在最近 20 条。
- 可选 `caseId`（非空、最多 100 字符）进一步收窄到指定案例，用于点击旧结果时确认当前可访问性。仍检查当前身份、查询词、状态和来源；不返回曾经缓存的正文。
- 响应 `Cache-Control: private, no-store`。成功 `data` 如下：

```json
{
  "items": [{
    "caseId": "案例 ID",
    "title": "实际案例标题",
    "excerpt": "从实际案例正文截取的摘要",
    "contentVersion": 1,
    "visibility": "PUBLIC",
    "sourceCount": 1,
    "updatedAt": "ISO 时间"
  }],
  "page": 1,
  "pageSize": 20,
  "total": 1,
  "hasMore": false
}
```

无命中/指定目标已撤回、转内部或失效：`200`，`items=[]`，不泄露目标是否存在。未登录 `401`、无权 `403`、非法参数 `400 VALIDATION_FAILED`，故障沿用统一失败信封。摘要最多 160 字符加省略标记，来自真实正文，不含原备案 ID、作者或照片字段。

课设规模下沿用公开目录的完整扫描方式，匹配候选后逐条核对，最后分页；没有新增数据库索引、迁移或通用搜索系统。数据量明显增长时再优化查询，不把该实现描述为适合大规模搜索。

## App 入口与状态

- 「知识与帮助」保留 AI 主按钮及折叠分类；「全部指南」打开左右分类目录，帮助区搜索图标打开知识搜索。
- 指南目录右上角也可进入搜索；全部/指南/案例切换反映真实查询类型。游客仅查询指南，案例区域提示登录，成功后续接原搜索。
- 搜索词、类型改变或离开页面时使旧代失效，清空不发请求。分页失败不推进页码，重试同一页；返回从服务端刷新案例，保留查询和类型。
- 案例点击前按 `caseId` 复核；客户打开原公开详情，工作人员打开授权案例详情。原始维修备案与 AI 案例不合并为一个搜索类型；本轮不搜索原始备案。

共享服务器需部署本批后端才能使用新增案例查询；旧版本返回 404 时 App 展示真实错误，不用最近一页或模拟结果兜底。当前验证部署见 [验证记录](../../docs/verification/issue-76.md)。
