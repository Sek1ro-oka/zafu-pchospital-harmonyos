## 目标、优先级与依赖

优先级 **P2，完整功能补齐**。迁移 Web 已实现的统计/榜单与完整管理功能，并补齐关于/手册入口及导出维护工具。依赖 08 的写通道，使用 09 的客户/备案对象、10 的活动管理页面与接口。先读 [公共基线](README.md)；这是模块 Issue，允许多个 PR 逐步交付，不要求一次写完所有管理页。

## 代码起点与负责边界

- 后端 `features/analytics/`、`admin/`、`members/`、`accounts/`、`invitations/`、`recruitment/`、`skills/`、`repairs/`；`/api/v1/admin/*` 和 `/member/analytics`、`/member/rankings`。
- Web `src/app/admin/`、`src/app/member/rankings/`、`src/app/about/`、`src/app/docs/` 及导出/历史导入工具为参照。UI 重新用 ArkUI 组织，不复制 React 页面。
- 本模块负责管理导航、统计与其余管理页；10 负责活动管理，09 负责备案详情/评论/客户基础契约。对这些页面做入口接线和授权跳转，不另建第二套服务。

## 交付清单

- [ ] 统计/榜单：已审核且未删除备案的次数/时长、月/学期/累计、分类分布、趋势、并列和本人排名；保留有效成员及日期口径，学期未配置/空数据/失败分别展示，不做志愿时长认证。
- [ ] 管理概览与权限入口：仅服务端授权账号可操作；ADMIN 不自动拥有成员个人数据或现场接待能力。
- [ ] 成员管理：查询/详情、资料/技能、启停、角色、密码重置、批量结果与排序/移动，保留最后管理员保护和审计。客户账号最低限度支持查询、启停、重置密码，复用 08/09 对象，不强制建成员档案；批量和人员排序沿用成员业务。
- [ ] 邀请码管理：创建/列表/更新/撤销、绑定/次数/有效期。
- [ ] 招新管理：申请列表/筛选、审核、开通账号/失败重试、导出；公开招新入口连真实接口，不把客户注册当招新。
- [ ] 维修备案管理：列表/筛选、审核/批量审核、退回理由、带理由和版本的异常修正、软删除、典型/疑难；调用现有详情/审核页。标记、修正、删除必须保留 #40 证据失效/重整规则。
- [ ] 分类/技能管理：创建/编辑、启停、排序/移动与引用约束；接入 10 的活动管理入口。
- [ ] 评论治理、审计日志/操作类型筛选；只暴露授权范围。
- [ ] 公开展示设置：迁移 Web 已有配置页及校验/审计；目前不新增公众统计/榜单消费接口，明确配置的实际生效范围。
- [ ] 导出：维修 CSV/XLSX、招新 CSV，复用权限/筛选/行数限制/内容安全处理；原生下载、保存或分享真实文件，失败有反馈。
- [ ] 保留/选择性同步历史维修导入 CLI、合成样本及必要结构；只验证工具，不迁移原 Web 数据，不新增 App 导入页面，不让普通成员使用管理工具。
- [ ] 关于/联系/公开招新入口复用真实内容；知识手册完善目录、Markdown 图片/链接与来源，沿用既有公开快照，不扩展公告 CMS。
- [ ] 各管理 API 写入按 08 公共通道适配，按子项更新契约、实际状态和验证记录。

## 必要验收

1. 用合成实验备案验证月/学期边界、待审核/删除排除、次数/时长与并列；保留课设已经验证的上海日期处理，不直接用 Web 差异覆盖。
2. 管理员逐项完成交付的真实动作，成员/客户直接请求管理 API 被拒；自停用/最后管理员/版本冲突等采用原 Web 限制。
3. 管理客户不创建 MEMBER，重置后强制改密接入 08；成员开通、角色、批量部分失败按原服务规则返回，不宣称全成功。
4. 备案修正/删除/标记变化后旧 AI 证据不再被检索或引用；导出打开真实 CSV/XLSX并核对筛选，不只测下载按钮。
5. 历史工具仅用合成样本预览/执行/重复执行；不读取原 Web DB/备份。原生手册实际打开图片/章节链接，无法访问有明确状态。
6. 每个 PR 只跑受影响统计/权限/状态/导出用例及必要 DB 回归，后端 lint；ArkTS 构建 HAP并做本次管理页的 DevEco 模拟器操作。最后列出全部子项状态，未完成时保留 Issue 打开。

## 建议交付顺序与开工提示词

建议 PR 顺序：统计/管理壳 → 成员/客户账号和邀请/招新 → 备案管理/字典/审计 → 导出/设置/内容/维护工具；不创建固定排期或额外审批流程。
