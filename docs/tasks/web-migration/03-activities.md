# 10 活动闭环（Web 功能迁移 3/4）

认领与进度：[Issue #62](https://github.com/Xiaoyuan-114/zafu-pchospital-harmonyos/issues/62)；前置 [#60](https://github.com/Xiaoyuan-114/zafu-pchospital-harmonyos/issues/60)，与 [#61](https://github.com/Xiaoyuan-114/zafu-pchospital-harmonyos/issues/61) 对齐备案和个人页入口。

## 目标、优先级与依赖

优先级 **P1，主功能**。把当前仅有的活动列表接成报名、本人查询、工作人员签到/接待闭环，并迁移活动管理。依赖 08 的登录与写通道，使用 09 的备案创建契约及“我的”入口。先读 [公共基线](README.md)；原 Web 数据不迁移。

## 代码起点与负责边界

- 后端 `features/repair-activities/`、`/api/v1/repair-activities/*`、`/member/repair-activities/*`、`/admin/repair-activities/*`。
- App `features/activity/ActivityPage.ets`，参考 [活动](../../reference/my-huawei/community-huafen-feed.jpg)。
- 本模块维护活动、报名账号关联、本人查询、现场接待和活动管理；11 只提供活动管理入口，不重复实现。工作人员出勤记录与客户报名记录分开。

## 交付清单

- [x] 真实活动详情：时间/地点/状态/容量/报名窗口与条款；列表保留真实空态。服务公告、经验分享分类可显示未接入，不新增发布 CMS。
- [x] App 报名前登录，成功续接当前活动；新报名服务端绑定当前 userId，客户端不能指定他人归属；联系姓名/电话/故障类型/可选机型按 Web 校验，须同意实际条款版本。
- [x] 为账号关联提供课设 schema 迁移，旧匿名行的归属可为空；不凭手机号自动认领，不清空已有实验报名。Web 原公开匿名报名与手机号查询/编辑凭据继续有效。
- [x] “我的报名”从服务端归属查询，含分页、活动、签到/接待状态及详情；提供用户可用的修改能力，按实际 Web 状态规则保留。Web 未提供的随时取消/认领不自行增加。
- [x] 手机号查询旧匿名报名：沿用现有凭据、响应范围和状态限制，不能因号码相同就出现在账号列表或获得所有权。
- [x] 成员标记活动出勤、签到队列、待接待/已接待看板、接待草稿及未接待排队撤回。按 Web 条件生成/关联 RepairRecord 草稿；与 09 对齐字段，活动流程无需创建 RepairOrder。
- [x] 成员取消本人出勤：未成功做过本场签到/类型调整/撤回/接待时可取消；保留历史与唯一行，已处理永久拒绝，兼容旧审计并与现场写事务互斥；支持幂等和合法重新出勤。
- [x] 同步 Web 最新签到故障类型调整、工作人员查询完整电话接口及审计；纯管理员无有效成员档案时不能伪装成接待成员。
- [x] 活动管理：管理员创建/编辑活动、时间/容量/状态，报名列表、授权修改/删除；保留与现场人员的权限差异。在“管理”提供该页面供 11 链接。
- [x] 同步接口文档：账号绑定/匿名查询区别、本人报名路径、状态可操作矩阵、接待生成备案及电话访问规则。

## 必要验收

1. 游客浏览活动 → 报名触发登录 → 续接报名 → 本人列表可见；另一账号不可查询/修改该账号报名，伪造 userId 无效。
2. Web 匿名报名及旧手机号查询仍可用；同电话的新账号不能自动获得历史行，匿名记录不被迁移脚本错误绑定。
3. 报名窗口、条款、容量、重复/并发报名按 Web 规则正确；只增加相关容量/归属回归。
4. 成员出勤 → 签到 → 接待生成真实备案 → 撤销按原状态约束；校验故障类型调整、完整电话权限、纯管理员身份不足。
5. 管理员创建/调整活动与报名成功；成员调用管理接口拒绝；“我的报名”与成员出勤不混在一起。
6. 在独立库验证关联迁移与上述真实 API 链路，相关 lint/测试；构建 HAP，并用 DevEco 模拟器跑报名/查询/现场看板。未执行的设备操作写明，不做无关审计。
