## 已确认的业务规则

1. 普通客户自主注册；沿用 QQ + 密码体系，客户默认无 MEMBER/ADMIN 角色、无成员档案。有效邀请码用于工作人员注册，保留原验证和权限；注册请求不得指定角色。管理员由授权管理操作产生。
2. 客户资料可编辑昵称、联系电话，头像先用默认头像；修改资料不自动改写历史报修/报名快照。成员昵称/技能与管理员资料编辑保留 Web 原权限。
3. 客户收藏维修指南和有效公开 AI 案例；成员保留 Web 的维修备案收藏。内容撤回、失效、转内部后，收藏项显示不可访问，不泄漏旧正文或证据。
4. 客户报修受理、进度、完成、取消产生本人站内消息；成员保留 Web 通知。支持未读数、已读/全部已读、删除、详情跳转；进入页面刷新即可，不建设系统推送。
5. 游客可浏览活动，App 报名先登录，新报名绑定当前账号并保留联系快照；“我的报名”从账号关系查询。旧匿名报名继续手机号查询，不凭号码相同自动认领。Web 原公开报名链路保持可用。
6. 客户报修 RepairOrder、工作人员维修备案 RepairRecord、活动报名是不同对象。RepairRecord 可独立创建，可来自报修建档或活动接待；审核状态不代替报修进度。
7. Web 已审核备案案例库与课设 AI KnowledgeCase 并存，明确来源。保留 #40 自动整理/相似合并/发布、权限过滤、撤回与证据失效守卫，不增加案例二次审核。
8. 导航仍为首页｜活动｜服务/工作台｜知识｜我的。管理能力放“我的/工作台 → 管理”，不增加顶层导航；客户只能访问本人对象和有效公开内容。

## 数据与范围边界

**不迁移原 Web 数据库数据。** 只复用代码、业务规则和所需数据库结构；不连接、导出或写入生产数据库，不复制真实人员、维修、报名、上传数据。沿用已有课设数据，新增数据来自课设注册、业务操作或独立测试库。历史导入工具若同步，只用合成样本验证，不执行生产数据导入。

- 课设仍用独立 MySQL，不用 Docker；开发库/测试库/共享实验库分开。不得在共享库跑清库测试；增加迁移不能清掉已有课设数据。
- 服务端 TS、Prisma、权限、状态、事务、幂等、统计和导出可选择性复用；React、DOM、Tailwind、Cookie 操作需用 ArkUI/原生网络和文件能力重做。
- 部分 Web 写路由仍只调用 `assertSameOrigin`，现有 GET 支持 Bearer 不代表写请求已适配。08 提供公共通道，其余模块适配自己负责的路由；保留 Cookie + Origin 和 Native Bearer + 客户端标识的分流。
- Native 无 PATCH 枚举时可沿用 POST 别名共享处理函数，不能复制两份服务逻辑。
- Web 最新新增 rememberMe、设备主人姓名/电话、历史导入暂存和活动电话查询；按模块选择性同步。**不可覆盖整个 backend/schema**，保留课设 RepairOrder、AI、案例证据及已验证日期处理。
- 原 Web 的公开展示设置目前负责配置存储/校验，不能当作已实现公开统计/榜单。公告/经验发布 CMS、具体预约时段、设备绑定、购物、系统推送、短信找回、头像上传不在本轮新增范围。

## 最少协作与验收

- 各模块负责自己的 DTO、服务、接口和页面；公共会话/鉴权由 08 维护。迁移文件使用唯一模块名称；公共 schema、Routes、ProfilePage 等有交叉时先在 Issue 说明，再合并最新 main，避免整文件覆盖。
- 09 提供客户资料、收藏、通知的契约；10 提供报名关系与查询；11 调用现成契约，不重复建模。遇到代码事实与任务书冲突，记录具体位置并找技术主线对齐，不凭推测放宽权限。
- 交付更新对应接口文档、README 实际状态，附简短验证记录。真实空数据和未接入入口明确显示，不硬编码结果。
- 只读页面检查真实返回及加载/空态/失败；写操作检查真实成功和关键权限/状态失败；涉及并发、版本、幂等才加相应回归，不做无关全仓审计。
- ArkTS 改动构建 HAP，在 DevEco 模拟器实际操作本模块页面；模拟器和真机证据分开记录，没有验证的范围写清。后端改动执行相关 lint/测试，改 schema 运行独立库迁移与受影响 DB 用例；PR 保持现有 `backend-check` 门禁。
- 从最新 main 建功能分支，提交推送并开 PR，正文 `Refs #<模块Issue>`；分批 PR 不提前关闭整个 Issue。普通 Merge 合入，禁止直推 main/强推/删除 ref，不要求额外审批。
- 共享服务器依赖安装和构建只在本机 WSL/Linux 完成；服务器运行产物。开发者先本地验证，部署由技术主线统一推进，避免互相覆盖正在使用的后端。

## 通用开工提示词

> 认领本模块 Issue。先读 AGENTS、README、开发方案、本目录公共基线和对应任务书，检查最新 main 与固定 Web 源码。按 Issue 实现真实原生功能，选择性复用现有后端；不迁移原 Web 数据，不重写其他模块，不伪造完成状态。先确认已有接口与缺口，再按任务书子项交付；需要公共契约或范围决策时在 Issue 记录并与技术主线对齐。只做本次相关测试和模拟器验证，构建在本机执行。使用功能分支与 PR，保留他人修改；提交后报告 SHA、接口、验证证据和未完成项。技术主线审查后通过普通 Merge 合入。
