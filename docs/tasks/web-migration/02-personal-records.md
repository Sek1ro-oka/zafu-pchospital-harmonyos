- [ ] 客户资料读取/编辑昵称与联系电话，默认头像；权限限本人，修改不覆盖历史报修/报名快照。成员资料/本人昵称、技能、授权的其他成员资料按 Web 原规则接原生页面。
- [ ] 客户收藏维修指南与有效公开 KnowledgeCase，支持收藏/取消/分页和跳转；使用稳定来源 ID，收藏恢复/重复请求不产生多份。成员保留 RepairRecord 收藏，不混淆对象。

- [ ] 工作台接本人真实维修汇总、近期备案及消息/收藏摘要；统计展示采用服务端口径。

## 必要验收

1. 两个客户分别操作，A 不能读/改 B 的资料、收藏、消息或报修；普通客户不能读取成员档案、内部案例或原始备案。
2. 编辑客户资料后旧单/旧报名联系信息保留；成员昵称/技能修改不越过管理员编辑范围。
3. 收藏指南与公开案例 → 取消/恢复 → 打开；案例转内部/撤回后刷新不可访问，不泄漏缓存正文。分页/切换范围/迟到响应不串内容或锁住加载。
4. 真实报修受理/推进/完成/取消各触发正确收件人消息，重复写不重复发；消息已读/删除与详情跳转成功，原成员消息继续工作。
5. 工作人员独立建备案 → 照片 → 提交 → 退回编辑 → 通过，Web 本人编辑限制保留；评论/回复/收藏可用；已审核备案与 AI 案例显示来源正确。
6. 对新增模型、通知事件与权限做最小 DB 回归；相关 lint/测试，HAP 构建和 DevEco 模拟器个人页/收藏/消息/备案操作。照片等未做真机的范围如实记录，不扩大全仓审计。
