# 08 公共接口与账号（Web 功能迁移 1/4）

认领与进度：[Issue #60](https://github.com/Xiaoyuan-114/zafu-pchospital-harmonyos/issues/60)。

## 目标、优先级与依赖

优先级 **P1，公共前置**。让客户能自主注册、两类账号能完成原生改密/保持登录，给其他三个模块提供可复用的写请求契约。认领前读 [公共基线](README.md)；现有登录已经实现，本任务是在其上补齐，不重新造会话体系。

## 代码起点与负责边界

- 课设 `backend/src/features/auth/`、`features/accounts/`、`features/invitations/`、`src/lib/auth/`、`src/app/api/v1/auth/`。
- App `core/auth/`、`core/network/`、`features/auth/LoginPage.ets`、`features/home/HomePage.ets`。
- 先读 [现有原生会话契约](../../../backend/docs/native-client-api.md)。现文档的 30 天会话是现状；Web 最新 rememberMe 的普通 24 小时/保持登录 30 天是待同步目标，不能只改文档。
- 本模块负责客户账号身份、注册、邀请码原生注册、改密/令牌轮换、会话及公共写通道。客户资料/收藏/消息归 09，活动归 10，管理页面归 11；其他模块依公共函数适配自己路由。

## 交付清单

- [ ] 盘点 Cookie/Bearer、Origin、强制改密、注册和错误码；在原生契约写清每条通道。
- [ ] 提供公共写请求校验：Cookie 沿用 Origin；Native 走 Bearer 与客户端标识。客户端标识不是身份凭证，仍须服务端鉴权。公开注册按现有校验/限流做独立入口，不伪造 Origin。
- [ ] 客户自主注册：QQ、密码/确认密码，昵称/联系电话可在个人资料补充；复用现有规范化、密码策略和唯一身份约束。重复 QQ 返回明确冲突，不改写已有账号或凭手机号认领他人账号。
- [ ] 注册产生客户身份，不创建 MEMBER 档案、不接受 roles/权限等客户端赋权。注册成功进入登录后的续接逻辑；采用返回会话还是注册后登录写入契约，不留下半登录状态。
- [ ] 有效邀请码注册工作人员，保留使用次数/到期/绑定、并发与失败规则；普通客户注册和邀请码注册入口名称清楚。注册服务不擅自覆盖既有账号身份。
- [ ] 原生修改密码：普通改密与首次/管理员重置后的强制改密；成功返回并安全保存轮换后的 Bearer，旧会话按既有策略失效。强制改密账号能访问所需会话/改密/退出入口，其他业务仍受限制。
- [ ] 同步 Web rememberMe 的 schema/迁移和会话服务；普通 24 小时、保持登录 30 天，改密轮换保留选择；App 默认保持登录并允许用户关闭，启动恢复始终向服务端验证。
- [ ] 登录/注册/改密支持请求中、防重复、错误/重试和取消；游客首页和登录后续接原操作继续有效，改密不丢失续接目标。
- [ ] 接口文档列出真实路径、请求/返回字段、身份、强制改密与冲突行为，供 09/10/11 直接接入。

## 先交付什么

先用一个基础 PR 交付公共写通道与身份/会话契约，再交付注册和改密页面；Issue 内给出已可用契约及 commit/PR，不必等整个模块关闭才让其余组员工作。新增 schema 只作用课设库，不迁移原 Web 数据。

## 必要验收

1. 新客户真实注册 → 登录 → 服务器返回客户身份 → 重启恢复 → 退出；重复账号失败，伪造角色无效。
2. 邀请码成功产生工作人员身份；无效/到期/次数耗尽失败，客户注册不消耗邀请码。
3. 普通改密与强制改密真实跑通，新令牌可用、旧令牌按契约失效；本地保存失败不展示已登录成功。
4. Web 带 Origin 的 Cookie 登录/写入行为保留；Native 不传假 Origin；无凭证/错权限/缺标识按契约失败。
5. rememberMe 两种到期时间及轮换可用确定时间测试验证，不实际等待一天；保留游客与登录续接的一次模拟器回归。
6. 改 schema 在独立开发/测试库迁移；执行相关鉴权/注册单测与 DB 检查、后端 lint/build、HAP 构建和 DevEco 模拟器注册/改密操作。不增加无关测试或审计。
