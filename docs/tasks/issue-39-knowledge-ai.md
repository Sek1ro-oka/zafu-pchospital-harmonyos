## 4. 文档导入与索引

来源为 [ZAFU-PCHospital-Doc](https://github.com/ZAFU-PCHospital/ZAFU-PCHospital-Doc)。本次核查的 `main` 提交为 `48f43637c8f4be87a7a751feb04defd7e0426849`，可作为首批快照；更新时显式选择新提交并记录。

1. 读取 `src/SUMMARY.md` 中实际存在且有正文的 Markdown，跳过空链接、纯目录和占位内容。README 中列出的规划章节不算已有知识。
2. 复制首批实际 Markdown 与来源清单到本课设仓库，保留来源说明，不复制嵌套 `.git`。新成员克隆后可用同一快照构建索引，无需修改上游。
3. 按标题与段落分块，保留标题层级、正文、源路径、行范围、来源提交、内容哈希、可见范围、块 ID。控制块长，尽量保留完整步骤、表格与代码段。
4. 文档含相对链接、脚注与图片。保留影响证据理解的链接及脚注，原文链接按固定提交生成并正确编码；图片不做 OCR，也不把未读取的图像细节当作证据。
5. 首批文档是公开资料，统一 `PUBLIC`。预留 `STAFF` 等内部可见级别，以服务端身份过滤，不能由请求里的 role 指定。
6. 小规模向量与必要元信息写入本地索引文件，后端加载后计算相似度，不增加数据库服务。生成索引、缓存和临时文件加入 `.gitignore`，不要求成员提交机器相关产物。
7. 缓存键包含 provider/model、维度、分段规则版本及内容哈希；未变化的块不重复调用 embedding。删除的正文须从新索引移除。模型或维度不兼容时要求重建，不混用新旧向量。
8. 查询与文档使用同一 embedding 配置；检查向量非空、数值有限、维度一致。索引构建失败时保留上一份完整索引，避免半成品覆盖。

提供两条简单命令，例如 `knowledge:sync` 与 `knowledge:index`；名称可调整，但说明必须能让组员完成「获取快照 → 配置模型 → 建索引 → 启动」。不引入自动同步后台服务。

## 5. 检索与回答

### 检索

- 中文关键词检索使用 BM25 或明确的相关性排序，保留机型、英文软件名、错误码、事件 ID 等精确词；不只靠整句 `includes`。
- 同时进行向量相似度检索，使用简单的排名融合（例如 RRF）合并、去重并选少量相关片段。不要直接相加量纲不同的原始分数。
- 可见性检查在片段送入模型前执行；源详情接口也检查权限。不允许因向量命中而跨越可见范围。
- 相似度靠前不代表一定相关。为无命中和弱证据设置明确行为，用实际样本调整；不强迫每个问题都返回答案。
- embedding 请求失败时可以明确降级为关键词检索，并返回实际 `retrievalMode` 和降级说明；无可用正文或索引损坏时明确报错。不得宣称降级请求经过向量检索。

### 多轮问答

- 当前问题结合有限的本次对话上下文确定检索意图，支持「这个怎么检查」等追问；不能只拿最后一句做检索。
- App 持有本次消息，后端按请求处理，不持久化聊天记录。限制历史轮数、单条长度、请求体及输出长度，具体默认值写进契约。
- 身份由服务端会话确定；历史只接受需要的 user/assistant 消息，不接受客户端注入 system 指令。历史中的答案、来源 ID 和文档内容均不能被当成授权事实。
- 回答只依据本次授权证据，区分可能原因和已确认事实；不得猜测收费、耗时或未记录的根因。拆机、注册表修改、磁盘写入等建议须保留原文中的适用条件和注意事项，客户信息不足时先澄清。
- 允许 `answer`、`clarify`、`insufficient_evidence` 等明确状态。澄清问题可以没有引用；实质性知识结论需要相关证据。
- 给模型使用后端生成的引用 ID；返回前校验 ID 只来自本次授权候选，并检查对应内容存在。引用 URL 和正文由后端生成，不采信模型编造的 URL。引用 ID 合法不代表结论正确，样本验收仍要人工核对支持关系。
- 只有确认无依据时才展示资料不足；provider 超时、限流、错误配置或坏响应分别作为请求失败处理，不能伪装成「知识库没有答案」。不添加无限重试。

## 6. 最小接口契约

建议以下接口；可根据现有代码微调，但须先记录并同步 ArkTS 类型。

| 接口 | 职责 |
| --- | --- |
| `POST /api/v1/knowledge/search` | 检索问题，返回实际模式、候选证据和来源 |
| `POST /api/v1/knowledge/chat` | 问题＋有限历史，返回状态、回答或追问、引用、实际检索模式 |
| `GET /api/v1/knowledge/sources/[id]` | 返回有权访问的引用章节正文、定位、版本、原文链接 |

- 沿用 `{success,data,meta}` / `{success,error,meta}` 和现有 requestId；错误码同步统一定义。
- 面向已登录客户和工作人员，复用原生 Bearer＋`X-Client-Type: native` 通道。不改变 Web Cookie/Origin 规则，不伪造 Origin，不因客户现有 permissions 为空而误判客户不可问答；核实原有账号状态和会话检查行为。
- 不开放任意 URL 抓取或任意文件路径读取；来源详情通过索引 ID 查已导入内容。
- 引用至少包含 `sourceId`、标题、章节、证据片段、版本和原文 URL；详情提供可定位的源正文。返回实际索引版本，过期 ID 有明确结果，不能悄悄指向其他正文。
- 检索、问答和查看来源均不产生报修单、不更新维修记录。

## 7. 原生页面交互

- 客户和工作人员使用同一知识入口，服务端控制资料范围。
- 原生问答页包含消息区、输入、发送、请求中状态、清空本次对话。内容可滚动，键盘弹出时输入与发送仍可操作。
- 发送中防重复；失败保留问题供重试，避免重试重复插入用户消息；会话过期交给现有上层流程回登录。
- 引用卡展示标题、章节及证据片段，点击进入原生引用详情；详情显示引用位置、来源版本，并可通过系统浏览器打开原文。
- 从引用详情返回仍保留本次聊天；退出问答功能或退出登录后清除。异步返回不得恢复已经清空的旧消息，不能把上一账号对话带给下一账号。
- 加载、失败和重试围绕当前请求或 sourceId；首次失败必须可见，切换来源后不能重试上一来源。
- 文本排版参考既有主题与五张参考截图；可先用普通文本与段落显示答案，不必开发完整 Markdown 渲染器。

## 8. 必要验收与检查

只补变更需要的测试，不做全面审计、覆盖率门槛、压测或评测平台。

### 自动检查

为有实际风险的逻辑增加少量单测：真实分段与来源定位、精确词与语义排名融合、向量维度不匹配、越权证据过滤、无依据/坏引用、模型失败、历史输入边界。使用小型明确标记的 fixture 或模型适配 mock，不在 CI 调用收费模型。

执行后端 `corepack pnpm lint`、`corepack pnpm test:unit`、`corepack pnpm build`；新增 API 用真实本机后端验证登录后的返回和会话失效。未改数据库模型时无需跑全套数据库测试；若确实修改数据库，只补受影响测试。ArkTS 修改须构建 HAP，使用英文工程路径，记录实际命令和结果。

### 小样本人工核验

选约 8–12 个真实问题，每项记录问题、预期证据、命中、实际回答/行为、引用支持情况。覆盖：

1. 原文覆盖的问题，以及换一种说法的同一问题。
2. 机型/错误码/事件 ID 等精确词；答案不得把相似型号混为一谈。
3. 多轮追问与信息不足的澄清。
4. 文档未覆盖的问题，返回资料不足。
5. 引用能定位实际正文，原文链接可打开；来源过期或不存在有可见反馈。
6. 使用明确标记的内部测试资料验证：客户检索/问答/详情均不可见，工作人员按授权可见；禁止虚构真实内部案例。
7. 模型或 embedding 超时/失败；明确降级或报错，页面可重试。
8. 更新或删除一份测试文档后重建索引，结果随数据改变。

用少量样本对比关键词与混合检索，报告实际差异和失败例，不预设向量检索一定更好。真实模型调用小批量执行，首条失败先排查，不批量烧请求。

有设备时验证输入/滚动、问答、追问、引用返回、清空和退出；无设备则标注「未真机验证」，构建与接口证据分开记录。全程不在 CI 配置模型 Key、启动数据库或增加工作流。
