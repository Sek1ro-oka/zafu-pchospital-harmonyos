## 2. 真实模型样本（开发库 + 真实 DeepSeek / bge-m3，脚本未入库）

经真实链路建立备案（客户建单 → 工作人员受理/完成 → 建档 → 编辑 → 真实 PNG 上传 → 提交 → 管理员真实审核），
再经真实模型整理。**如实记录全部结果（含两次未达预期）**：

| 样本 | 故障内容 | 真实结果 |
| --- | --- | --- |
| A | 键盘进水后按键失灵（维修内容写「排线氧化」） | 独立建案 PUBLISHED；问答换措辞命中并打开 ✔ |
| B | 咖啡洒到键盘（维修内容写「清理排线与接口水渍」） | 真实模型判为「不同故障」→ **独立建案**（未合并 A） |
| C | MacBook 风扇积灰异响 | 独立建案 ✔（与 A/B 不同机型/分类） |
| D | 键盘进水、按键无反应（与 A 同故障不同措辞） | **自动合并进 B 的案例**，保留两来源（来源 2、证据 4+5 条）✔ |

说明：
- 未合并预期差（A×B）：模型给出的 `merge_reason` 认为氧化与水渍是不同故障，属模型判断而非缺陷；
  A 的案例材料中「故障现象」为「原文未提供」（备案材料没有故障描述字段），模型不推断——与
  「原文未知事实继续未知」的设计一致；
- 合并与保留两来源（含证据逐条、来源计数）由 D 的真实合并验证；
- 检索命中（真实模型问答）：
  - 员工问「笔记本键盘进水好几个键按不出字，一般怎么修？」→ `answer`，引用 2 条案例
    （B、A 的 `kcase_…`），两条引用都在来源详情页成功打开；
  - 员工问「MacBook Air 风扇灰尘很多噪音很大，该怎么清理？」→ `answer`，S1 命中 C 案例；
  - 检索接口核对：C 案例在关键词+向量混合检索结果第一位（0.095）。

### 客户侧权限（真实通道）

| 场景 | 结果 |
| --- | --- |
| 公开前：客户检索「键盘进水按键失灵」 | 案例引用 0 条 ✔ |
